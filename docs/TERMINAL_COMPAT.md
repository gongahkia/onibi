# SSH and terminal compatibility checks

Verified on macOS amd64, 2026-10-26, using OpenSSH 9.9p2 and tmux 3.8. The harness
starts a real loopback SSH daemon with temporary host/user keys, pins that host
key, requests an SSH PTY, and drives the actual Shack executable. It does not
modify the user's SSH configuration, authorized keys, known hosts or clipboard.

## Observed matrix

replacement preview, save, resize down to a tiny terminal and back, and clean quit.

These are terminal-protocol/profile tests through PTYs, not visual certification of
every desktop terminal application, font or physical VT100/Linux console. Unicode
checks use UTF-8 sessions. Clipboard replies are generated by the harness: actual
clipboard reads still depend on terminal policy and may be refused. The test checks
the encoded clipboard contents on the wire without writing the OS clipboard.

A separate nested workflow exercises **SSH → tmux → Shack → shell/Vim**: an
interactive shell, Unicode editing and saving in Vim, propagation of outer-terminal
size changes to the embedded PTY, Ctrl+] returning to editor controls, and cleanup
of the shell and a foreground process when Shack exits.

## Practical controls

- Use Ctrl+E for commands when a terminal cannot transmit a function key or a
  shortcut is intercepted. In tmux, Ctrl+B is normally the tmux prefix; use the
  **Toggle file tree** command or a configured alternative binding.
- Copy always updates Shack's internal clipboard. **Paste Shack internal
  clipboard** works even when OSC 52 is unavailable or blocked. Native terminal
  paste remains another option. Clipboard access through SSH/tmux depends on both
  layers; the harness enables `set-clipboard on` only in its temporary tmux server.
- Mouse handling depends on the terminal forwarding events. The matrix tests
  editor selection and right-click context actions, not an outer application's
  native mouse menu. All tested actions also have keyboard commands.
- Use a TERM value matching the actual terminal. The harness varies TERM to test
  each protocol profile; it is not a recommendation to misidentify a terminal.

## Reproduce

```sh
make build
python3 scripts/ssh_smoke.py
```

Development prerequisites: Python 3, OpenSSH client/sshd/ssh-keygen, tmux and Vim.
`SSHD_BINARY`, `TMUX_BINARY` and `SHACK_BINARY` override executable paths.
`SHACK_TERMINAL_PROFILES=xterm-256color,vt100` selects a smaller profile set; the
remote tmux and embedded-terminal workflows still run. The current user must be
able to run an isolated key-authenticated sshd on a loopback high port. All test
files, sockets, keys and processes are temporary.

The harness also reports first-output delay and terminal bytes for 20 ordinary
edits over encrypted loopback SSH. This measures local SSH/PTY delivery, excluding
terminal painting; it is not a WAN latency, packet-loss or low-bandwidth guarantee.
